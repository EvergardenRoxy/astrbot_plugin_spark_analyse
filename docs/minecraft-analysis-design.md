# Minecraft 报告分析改进设计

本次在 v1.0.8 的 main 上实现，作为 Unreleased 提交。目标是减少 Minecraft 性能初筛的误判，并让模型取得更完整的热点和时段证据；继续使用原有命令、配置、报告格式与只读查询，不扩大到 allocation/heap 分析。

## 1. 诊断必须说明适用范围

- Spark 明确提供 game_target_tps / game_max_ideal_mspt 时采用报告目标；缺失时回退到 20 TPS，或根据目标计算预算。原来 20 TPS 的负载分档按比例缩放，保持默认服务器的分档兼容。
- load/spikes 标注为结束时最近一分钟，单独提供五分钟指标。window_summary 保留全部采样窗口的极值及窗口 ID，window_load 表示至少有窗口负载升高，不表示整个期间持续过载。
- MSPT 中位数不能把 park/wait 样本定位到 tick 内或 tick 间。wait_kind 保留接口但返回 unknown，配套说明慢 tick 筛选与时间范围。模型可以结合路径、同期窗口继续分析，不能用固定规则强制得出空闲结论。
- 仅服务端平台生成服务器 TPS 负载标签；客户端、代理、普通应用不作此推断。

好处：支持 Minecraft 自定义 tick rate，防止采样范围不一致造成错误结论。代价：部分过去的确定性结论变为未知，需要增加一次路径/窗口查询。

## 2. 线程角色需要正面证据

默认按名称分组的服务端 `Server thread` 标为 server_tick；客户端 `Render thread` 标为 client_render；明确 Folia 平台上的 `Region Scheduler Thread #数字` 标为 region_tick。其他名字或按池/合并分组均为 unknown。角色来自平台和名称，不来自采样耗时排名。

Folia 逐区域保留证据，不选出一个“全服主线程”。证据包仍最多四线程，省略数量明确输出。未知名字的线程仍可查询，不能凭名猜行为。这个保守识别可扩充，但每次扩充应有具体平台证据和测试。

## 3. 热点分为方法汇总与原始节点

新增 methods 视图，按完整 class/method/method_desc 与映射来源分组，累加各原始节点的 self。不同重载、不同注入来源保留独立记录，避免互相归责。

每组保存 self 最大的原始节点作为代表，输出 occurrences（树节点出现数，并非调用次数）、代表节点自身耗时、代表 inclusive。path 是这个节点的一处路径，不能将全方法汇总成本归给它。聚合结果不提供含义混淆的“inclusive 总和”，避免递归重复累计。

默认 evidence_pack 使用 methods 排名，仍最多五热点/线程、八帧/路径。hotspots/children/callers/search 原始查询保持可用；工具说明指引模型从代表节点继续追查。

服务端主线程有可靠计数时提供 self_ms_per_tick：普通报告用总 tick 数，慢 tick 报告用入选 tick 数；单窗口仅在未筛选且有窗口 tick 数时计算。Folia 区域不使用全服 tick 数归一化。

好处：发现分散在多条调用路径的物流、机器、实体 AI 等公共热点，同时保留追查路径。代价：方法分组需要与不同签名数量成比例的临时内存，继续受解析 worker 内存、节点和超时上限约束。

## 4. 来源按具体程度解析

优先 method_sources，其次 line_sources，再次 class_sources；输出证据层级和方法描述符。不把模组来源视为卡顿因果，不增加任何自动卸载、删存档建议。方法聚合使用未截断的原始签名/来源作为键，展示字段仍截断。

## 5. 有界输出覆盖全部窗口

概览仍只给前 120 个窗口详情，但额外扫描所有已记录窗口，保留最低 TPS、最高窗口中位数、最长 tick、玩家/区块峰值及各自窗口 ID。新增 windows 查询，支持分页和指定 window 直查；异常位于概览或分页上限之外时仍可按摘要 ID 取得该窗口详情，再查询同窗口 methods。

所有极值是“报告中记录的窗口”，不保证完整覆盖现实发生过的卡顿。指标缺失保持 null。窗口长 tick 判断基于摘要中的最大值及它同一窗口的中位数，不是完整的逐 tick 事件检测。

人均区块数从区块峰值所在的同一窗口计算，不再分别取两个不同时段的峰值。提示词将该比值作为检查视距/强制加载的线索，不作故障判据。

## 6. 兼容与限制

- 不修改配置键、默认权限、下载地址、体积限制或队列行为；版本暂保留 1.0.8，记录在 Unreleased，等待正常发版。
- 历史比较新增目标 TPS、预算、线程分组条件。旧记录缺字段时保守标记条件不同；仍能读取和删除。
- 没有加入自动反混淆或全量 metrics 解码；它们需要单独评估映射服务、版本兼容和上下文开销。
- Observable 单独报告仍按默认 tick rate 估算；当配对 Spark 有自定义目标时，提示词要求不把 Observable 默认标签当作过载证据，优先使用绝对每 tick 耗时。
- 没有运行真实 AstrBot 或 Minecraft 服务器；确定性计算、查询协议和打包通过自动测试及合成 worker 验证，模型回答质量仍需真实场景评估。

## 7. 验证

新增 Minecraft 回归用例先在旧实现上运行，确认失败后实现。覆盖自定义目标、筛选采样、线程角色、来源优先级、重载/递归聚合、同签名不同来源、每 tick 分母、异常窗口、玩家区块同期关系、非有限数值与真实 worker 查询。

本地 Python 3.12 完整套件 236 项通过（原 216 项，新增 20 项）；插件打包及 ZIP 完整性检查通过。Python 3.13 留给现有 CI 矩阵验证。

额外通过真实解析 worker 处理 100,000 个不同方法节点：解析、概览和一次 methods 查询合计约 1.61 秒，概览 4,511 字节，查询返回 20 行和下一页位置。该结果仅是本环境单次合成验证，不代表百万节点或真实大型报告的性能保证。
