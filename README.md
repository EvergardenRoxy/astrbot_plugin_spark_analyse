# Spark 报告分析

在 AstrBot 聊天中发送现状和 Spark 报告链接，即可获得 Minecraft 性能分析与排查建议。面向 Minecraft 1.20.1 及以上的 Forge / NeoForge 服务端，也可以询问报告中的 JVM 参数、内存和 GC 表现。

## 功能

- 自动读取 Spark 报告，分析 TPS、MSPT、调用热点及相关运行信息。
- 使用单独配置的分析模型，支持按顺序切换备用模型。
- 输出适合 QQ 阅读的中文纯文本，可自定义回复提示词和收到报告时的确认消息。
- 支持管理员、管理员与白名单、所有人三种调用权限。
- 缓存原始报告，默认从最近一次调用起保留 72 小时，重复提问无需重复下载。
- 可选保存分析历史，比较同一服务器或问题的多份报告。

## 安装与配置

需要 **AstrBot ≥ 4.16.0**。

1. 将本插件安装到 AstrBot 的插件目录，或使用插件管理页导入发行压缩包。
2. 在 AstrBot 使用的 Python 环境安装依赖：`pip install -r requirements.txt`。
3. 在插件设置中选择“用于分析报告的模型”。请使用支持工具调用的模型。
4. 按需选择备用模型、调用权限和缓存时间，保存设置并重载插件。

## 开始使用

直接发送描述与报告链接，例如：

```text
帮我分析这个 Spark 报告，最近探索新区时卡顿：
https://spark.lucko.me/<报告ID>
```

也可以使用命令：

```text
/spark https://spark.lucko.me/<报告ID> 最近机器多了以后掉TPS
```

询问具体问题时可以写：

```text
帮我分析 https://spark.lucko.me/<报告ID> 中的 JVM 参数和 GC，有没有优化空间？
```

收到请求后，插件发送一次确认，完成后直接回复分析。模型调用失败时会按配置顺序尝试备用模型。

如果希望由主聊天模型决定何时分析，在人格的工具列表启用 **`spark_analyze`**，并关闭插件的自动分析开关。该工具将任务交给专用分析模型，在后台完成后发送结果。

## 历史比较

打开“保存分析历史”，使用相同的服务器和问题标签：

```text
/spark https://spark.lucko.me/报告ID server=生存服 problem=新区卡顿
```

再次采样后，添加 `compare` 比较最近一次记录：

```text
/spark https://spark.lucko.me/新报告ID server=生存服 problem=新区卡顿 compare 预生成地图后再次采样
```

不填写标签时，插件根据系统与 CPU 信息生成大致的服务器标签，并为问题分类。同配置的机器可能具有相同标签，需要准确区分时请自行填写 `server=` 和 `problem=`。

历史按会话和发送者分别管理，保留 30 天。`/spark forget` 清除你在当前会话的分析历史；清除前需要开启历史保存。

## 常用设置

- **用于分析报告的模型**：处理 Spark 分析的专用模型。
- **备用分析模型**：首选失败后，从上到下尝试。
- **收到报告后的回复**：自定义确认文字，留空关闭。
- **自动分析报告链接**：识别带有分析意图的消息并启动分析。
- **谁可以使用**：选择管理员、管理员与白名单或所有人。
- **允许使用的用户**：填写平台用户 ID，在白名单模式下生效。
- **允许使用的聊天**：限制使用会话，留空不限制。
- **分析回复要求**：自定义分析重点和表达方式，留空使用默认要求。
- **报告缓存时间**：单位小时，默认 72 小时，每次使用重新计时。
- **保存分析历史**：开启后可进行历史比较。
- **下载等待时间 / 解析等待时间**：分别设置报告下载和解析的最长等待秒数。

## 数据存储

数据位于 `data/plugin_data/astrbot_plugin_spark/`：

- `profiles.sqlite3`：原始报告缓存，与分析是否成功无关，过期记录在访问缓存时清理。
- `history.sqlite3`：开启历史功能后保存的报告概览和分析结果。

两个数据库独立存储。关闭历史功能或清除个人历史，不会删除报告缓存。报告信息会发送给你选择的模型，数据库请妥善保管。
