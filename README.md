# Spark 报告分析

在 AstrBot 聊天中发送 Spark 报告链接（或 `.sparkprofile` 文件），即可快速了解服务器现状、疑似问题点和建议先做的检查，也可以询问 JVM 参数、内存和 GC 表现。支持 Forge、NeoForge 模组端，以及 Paper、Folia、Leaf 等插件端的报告，也能分析 [Observable](https://github.com/tasgon/observable) 报告。

插件定位是快速排查，不追究根因：结论由模型根据报告自动给出，都是“疑似”问题点。需要深入定位时，请把报告交给有经验的管理员或开发者。

文档分工：[CHANGELOG.md](CHANGELOG.md) 记录每版变化，[checklist.md](checklist.md) 说明改了什么、怎么核对，[handoff.md](handoff.md) 是给工程师的技术记录。

## 功能

- 读取 Spark 报告链接或 `.sparkprofile` 文件，分析 TPS、MSPT、调用热点和运行信息；使用单独配置的分析模型，可设备用模型。
- 内置诊断手册：按报告的目标 TPS 和 tick 预算判断负载，区分“最近一分钟”与整个采样期间的异常；等待性质证据不足时保留未知。按“现状、疑似问题点、建议先做的检查”回复，并给出后续采样命令。
- 按完整方法签名汇总分散的热点，结合方法、行号、类的来源映射识别模组或插件；Folia 区域线程分别分析。
- 三种调用权限：管理员、管理员加指定用户、所有人。
- 缓存链接下载的原始报告（默认 72 小时）；可选保存分析历史，用 `compare` 比较多份报告。
- **新：首次分析附带四联图**（见下文，默认关闭）。

## 安装与配置

需要 **AstrBot ≥ 4.16.0**。

1. 安装插件到 AstrBot 插件目录，或在插件管理页导入发行压缩包。
2. 在 AstrBot 的 Python 环境执行 `pip install -r requirements.txt`。
3. 在插件设置中选择“分析模型”（需支持工具调用）。
4. 按需设置备用模型、使用权限和缓存时间。默认只有 AstrBot 管理员可用。

## 开始使用

```text
帮我分析这个 Spark 报告，最近探索新区时卡顿：
https://spark.lucko.me/<报告ID>
```

也可以用命令，并附上现象或问题：

```text
/spark https://spark.lucko.me/<报告ID> 最近机器多了以后掉TPS
```

收到请求后插件先发一次确认，完成后直接回复；模型失败时按顺序尝试备用模型。一次只分析一份报告，其余请求排队（最多 3 份）；同一个人在同一会话里上一份未完成时不能再发下一份。

若希望由主聊天模型决定何时分析，在人格的工具列表启用 **`spark_analyze`** 并关闭“自动识别报告链接”。插件会在后台用专用模型完成分析，开始提示和结论由插件直接发送。

## 首次分析附带四联图

在设置中打开“首次分析附带四联图”即可，不需要额外命令，原有的链接、附件、命令和工具入口都适用。

- **内容**：深色四联图——tick/TPS/在线人数、堆与非堆内存及内存池、主线程模组/插件来源 Top 7、玩家延迟，右侧为 GC 摘要。缺少曲线数据时显示真实快照或“未提供”，不编造曲线。
- **只发一次**：同一聊天内同一份报告（按内容识别）仅首次成功发图，换用户、文件名或链接不会重复；记录保留 30 天，不同聊天独立计算。
- **只在文字分析成功后发送**：模型失败时不出图；出图失败不影响文字结论，下次提交可重试。
- **时区**：“图表时区”填 IANA 名称（如 `Asia/Shanghai`），默认 UTC，非法值回退 UTC。
- **注意**：来源榜按官方 Sources 口径统计，含子调用和主线程等待，来源之间可重叠、不能求和，也不是 CPU 占用或模组责任。不同面板的覆盖时间可能不同，图中会标注。当前不读取 GC 日志或 JFR。
- 绘图在独立进程中离线完成（最多 30 秒），使用包内约 1.5 MB 的中文字体子集；韩文和生僻字会显示为方框。需要 Matplotlib 和 tzdata（已在 `requirements.txt` 中）。

## 分析 Observable 报告

Observable 逐个记录实体和方块实体的 tick 耗时，适合回答“具体是哪些实体、机器、区块在拖慢服务器”；Spark 回答“整体卡不卡、时间花在哪”，两者互补。

```text
帮我分析这个 Observable 报告：
https://observable.tas.sh/p/<报告ID>
```

- 和 Spark 一样，只有提出分析请求（链接加“分析”“卡顿”等词，或 `/spark` 命令）才会读取。
- 同一条消息里同时给 Spark 和 Observable 报告会合并分析，并先核对游戏版本、加载器和采样时间；不一致时分开看待。
- 同一个人在“配对时间”（默认 30 分钟，0 为关闭）内先后分析两种报告时，后一次会把前一份当作背景，并在末尾注明。
- 一条消息最多一份 Spark 和一份 Observable；Observable 暂不支持历史对比和本地 json 文件；只通过 `observable.tas.sh` 读取，不跟随跳转。
- 报告压缩后不超过 16 MiB，解压后 Observable 不超过 48 MiB、Spark 不超过 128 MiB。采样太久导致超限时，请缩短采样，例如 `/spark profiler start --timeout 300`。

## 发送 .sparkprofile 文件

在服务器执行 `/spark profiler stop --save-to-file` 得到 `.sparkprofile` 文件（模组端在 `config/spark/`，插件端在 `plugins/spark/`），直接发到聊天即可。开启“自动识别报告链接”时，有权限的人发文件就会开始分析；能给文件附文字的平台（Telegram、Discord 等）可以在同一条消息写 `/spark 现象`。文件不超过 128 MiB，不缓存，文件名必须以 `.sparkprofile` 结尾。

插件只读取消息本身附带的文件，**不读取引用（回复）消息里的文件**：不同适配器还原被引用文件的结果不一致，并且回复任何文件消息都会触发分析。QQ（NapCat 等 OneBot 实现）发文件不能附文字，只能按报告本身分析，且必须开启“自动识别报告链接”；需要针对报告提问时请改发链接。已在 QQ 群（NapCat，AstrBot 4.28.2）实测通过。

## 历史比较

打开“保存分析历史”，用相同的 `server=` 和 `problem=` 标签提交报告，再次采样后加一个单独的词 `compare`：

```text
/spark https://spark.lucko.me/报告ID server=生存服 problem=新区卡顿
/spark https://spark.lucko.me/新报告ID server=生存服 problem=新区卡顿 compare 预生成地图后再次采样
```

不填标签时插件会按系统与 CPU 信息生成，同配置的机器可能相同，需要准确区分时请自己填写。没写 `problem=` 只按服务器标签比较最近一次记录。无法比较时结论末尾会说明原因。历史按会话和发送者管理，保留 30 天；`/spark forget` 清除你在当前会话的历史。

## 常用设置

- **分析模型 / 备用模型**：分析用的专用模型（需支持工具调用），不选择就不会分析，也不会改用主聊天模型；备用模型在出错时依次换用。
- **谁可以使用 / 指定用户 / 限定聊天**：权限默认仅 AstrBot 管理员（不是 QQ 群管理员）；指定用户填平台用户 ID；限定聊天填会话标识（发送 `/sid` 查看），留空不限制。
- **自动识别报告链接**：有权限的人发报告链接并提到“分析”“卡顿”“掉TPS”等词时自动开始，不需要 @ 机器人。
- **开始分析时的提示 / 分析回复要求**：自定义确认文字和回复重点；内置规则始终生效。
- **保存分析历史 / 报告缓存时间**：历史保留 30 天；缓存默认 72 小时，最多 64 份、合计 512 MiB。
- **首次分析附带四联图 / 图表时区**：见上文。
- **下载最长等待 / 解析最长等待**：慢网络可把下载等待设为 600 或 900 秒（默认 120 秒）。
- **下载报告时使用代理 / 代理地址**：默认关闭；开启后只有下载 Spark 报告走该 HTTP/HTTPS 代理（不支持 SOCKS），代理不可用时不会改为直连。Docker 里的 `127.0.0.1` 指容器自己。

## 数据存储

数据位于 `data/plugin_data/astrbot_plugin_spark/`：

- `profiles.sqlite3`：链接下载的原始报告缓存，与分析是否成功无关；`.sparkprofile` 文件不进入缓存。
- `history.sqlite3`：开启历史功能后保存的报告概览和分析结果。
- `chart_delivery.sqlite3`：聊天标识的哈希、报告内容指纹和出图状态，保留 30 天，不保存图片或玩家身份。`/spark forget` 不会重置它。
- `chart-*`、`spark-*` 临时目录：绘图和分析期间使用，结束即清理（PNG 最多留 10 分钟供适配器读取）；异常退出的残留在下次加载时清理。

三类持久数据互相独立。报告信息会发给你选择的模型，请妥善保管数据库。极端情况下图片已送达但进程在记录前退出，重启后可能再出一次图；记录保存失败时会提示。图表数据不进入模型提示词、历史或配对记忆。

### 分析口径

- “最近一分钟”是报告结束时的滚动指标，网页卡片可能显示最近五分钟；插件还会查看全部采样窗口的最低 TPS 和最高 MSPT，结束前恢复正常不会掩盖更早的异常。
- 热点占比是所在线程的采样占比，不是 CPU 使用率，也不是模组责任比例；汇总路径只代表其中一处调用位置。
- 报告没有目标 tick rate 时按 20 TPS 处理；客户端、代理和普通应用报告不用于诊断服务端负载。

## 已知问题

详细说明见 [checklist.md](checklist.md) 的“已知问题”。

- **报告内容可能误导分析模型**：报告里的文字和用户描述都会交给模型。插件已有多层防护（专用模型、唯一的只读查询工具、查询次数上限、规则要求不执行报告里的指令），不会泄露密钥或执行命令，结论超过 3000 字会被截断，外部链接会改为不可点击；但特意构造的报告仍可能让模型给出错误结论，请把结论当作参考。
- **部分关键限制没有自动测试保护**：100 万调用节点上限、每次模型尝试最多查询 8 次、查询者身份校验、AstrBot 退出后解析进程自行结束、“谁可以使用”取值未知时拒绝访问。它们目前正常生效，但删除其中任何一项现有测试都发现不了。
