# Spark 报告分析

在 AstrBot 聊天中发送现状和 Spark 报告链接（或 `.sparkprofile` 报告文件），即可快速了解服务器现状、找出疑似问题点和应先做的检查，也可以询问报告中的 JVM 参数、内存和 GC 表现。支持 Forge、NeoForge 模组端，以及 Paper、Folia、Leaf 等插件端（Bukkit 系）的报告。

插件的定位是快速排查，不追究根因：分析由模型根据报告自动完成，结论是“疑似”问题点。需要深入定位时，请把 spark 报告交给有经验的服务器管理员或开发者。

## 功能

- 自动读取 Spark 报告链接或 `.sparkprofile` 文件，分析 TPS、MSPT、调用热点及相关运行信息。
- 使用单独配置的分析模型，支持按顺序切换备用模型。
- 内置诊断手册：插件先算出负载判定（是否过载、有无偶发尖峰、tick 线程的等待是否为空闲），模型据此按“现状、疑似问题点、建议先做的检查”回复，并给出后续采样命令。
- 输出适合在聊天中阅读的中文纯文本，可自定义回复提示词和收到报告时的确认消息。
- 支持管理员、管理员与白名单、所有人三种调用权限。
- 缓存通过链接下载的原始报告，默认从最近一次调用起保留 72 小时，重复提问无需重复下载。
- 可选保存分析历史，比较同一服务器或问题的多份报告。

## 安装与配置

需要 **AstrBot ≥ 4.16.0**。

1. 将本插件安装到 AstrBot 的插件目录，或使用插件管理页导入发行压缩包。
2. 在 AstrBot 使用的 Python 环境安装依赖：`pip install -r requirements.txt`。
3. 在插件设置中选择“分析模型”。请使用支持工具调用的模型。
4. 按需设置备用模型、谁可以使用和缓存时间，保存后生效。默认只有 AstrBot 管理员可以使用；要让其他人使用，把“谁可以使用”改为“管理员和指定用户”或“所有人”。

## 开始使用

直接发送描述与报告链接，例如：

```text
帮我分析这个 Spark 报告，最近探索新区时卡顿：
https://spark.lucko.me/<报告ID>
```

也可以使用命令：

```text
/spark https://spark.lucko.me/<报告ID> 最近机器多了以后掉TPS
```

询问具体问题时可以写：

```text
帮我分析 https://spark.lucko.me/<报告ID> 中的 JVM 参数和 GC，有没有优化空间？
```

收到请求后，插件发送一次确认，完成后直接回复分析。模型调用失败时会按配置顺序尝试备用模型。

如果希望由主聊天模型决定何时分析，在人格的工具列表启用 **`spark_analyze`**，并关闭“自动识别报告链接”。消息中带有（或引用了）`.sparkprofile` 文件时，主聊天模型调用该工具不必填写链接，插件直接读取文件。主聊天模型调用该工具后，插件在后台用专用分析模型完成分析，开始提示和结论都由插件直接发送，主聊天模型不再额外回复（因此不会多消耗一次主模型调用）。在 AstrBot 4.27.0 以前的版本中，这一轮对话不会写入主聊天模型的对话历史，不影响分析本身。

报告解压后（或 `.sparkprofile` 文件本身）不能超过 128 MiB。连续采样数小时的报告常会超出，插件会提示缩短采样时间，例如 `/spark profiler start --timeout 300`（5 分钟后自动停止）。

### 发送 .sparkprofile 文件

服务器上执行 `/spark profiler stop --save-to-file`，报告会保存为 `.sparkprofile` 文件而不上传（模组端一般在 `config/spark/`，插件端在 `plugins/spark/`）。服务器连不上 spark 网站、上传失败时，spark 也会自动改为保存文件。

把这个文件直接发到聊天即可：开启“自动识别报告链接”时，有权限的人发送 `.sparkprofile` 文件就会开始分析，不需要附文字或关键词。想补充现象，或关闭了自动识别时，回复这条文件消息发送：

```text
/spark 最近机器多了以后掉TPS
```

QQ 等平台不能给文件附文字，所以用回复的方式；能附文字的平台（如 Telegram、Discord）也可以在发送文件时直接写 `/spark 现象`。文件不超过 128 MiB，不会缓存，再次分析时重新发送或再回复一次即可。其他扩展名的文件（如 `.sparkheap`）不会触发分析。

## 历史比较

打开“保存分析历史”，使用相同的服务器和问题标签：

```text
/spark https://spark.lucko.me/报告ID server=生存服 problem=新区卡顿
```

再次采样后，添加 `compare`（单独的一个词）比较最近一次记录：

```text
/spark https://spark.lucko.me/新报告ID server=生存服 problem=新区卡顿 compare 预生成地图后再次采样
```

不填写标签时，插件根据系统与 CPU 信息生成大致的服务器标签，并为问题分类。同配置的机器可能具有相同标签，需要准确区分时请自行填写 `server=` 和 `problem=`。

对比时，没写 `problem=` 就只按服务器标签找最近一次记录，不受问题描述用词的影响；写了 `problem=` 则只与同一问题标签的记录对比。没能对比时（例如没有开启“保存分析历史”、没有找到记录，或报告缺少系统信息而需要填写 `server=`），结论末尾会说明原因。

历史按会话和发送者分别管理，保留 30 天。`/spark forget` 清除你在当前会话的分析历史。关闭“保存分析历史”后不再写入新记录；已有记录仍可用 `/spark forget` 清除，超过 30 天的记录在插件加载时删除。

## 常用设置

配置页按以下顺序排列：

- **分析模型**：分析报告用的专用模型，需要支持工具调用。不选择就不会开始分析，也不会改用主聊天模型。
- **备用模型**：分析模型出错时，从上到下依次换用。
- **谁可以使用**：仅管理员（默认）、管理员和指定用户，或所有人。“管理员”指 AstrBot 管理员，不是 QQ 群管理员。
- **指定用户**：填写平台用户 ID（例如 QQ 号），只在“管理员和指定用户”模式下生效。
- **限定聊天**：只允许在这些聊天中使用，留空不限制。填写 AstrBot 会话标识（在聊天中发送 `/sid` 查看）。
- **自动识别报告链接**：有权限的人发送报告链接并提到“分析”“卡顿”“掉TPS”等词时自动开始分析，不需要 @ 机器人；发送 `.sparkprofile` 文件时直接开始分析。没有权限的人发送时插件不响应。
- **开始分析时的提示**：开始分析前发送一次的确认文字，留空则不发送。使用 `spark_analyze` 工具时这是唯一的开始提示，建议保留。
- **分析回复要求**：分析模型回复的重点、语气和长度，留空使用默认要求。插件内置的分析规则和诊断手册始终生效；仍是旧版默认内容的配置会自动更新为新版。
- **保存分析历史**：开启后可用 `compare` 与上次结果对比，记录保留 30 天。
- **报告缓存时间**：单位小时，默认 72 小时，从最后一次使用开始计时。
- **下载最长等待 / 解析最长等待**：报告下载和解析的最长等待秒数。慢网络可将下载等待设为 600 或 900 秒（默认 120 秒）；超时提示会说明卡在哪个阶段。传输体积仍限 16 MiB，解压后限 128 MiB。获取聊天中的 `.sparkprofile` 文件也按下载等待计时，文件限 128 MiB。
- **下载报告时使用代理 / 代理地址**：默认关闭，直接连接。开启后只有下载 Spark 报告会经过这里填写的 HTTP/HTTPS 代理（如 `http://代理主机:端口`，不支持 SOCKS），不使用 AstrBot 或系统的代理设置，也不影响模型的连接；代理连不上时不会自动改为直连。AstrBot 在 Docker 中运行时，`127.0.0.1` 指容器自己。地址里有账号密码时只填在本地配置中，不要发到聊天；插件日志不会记录代理地址。聊天中发送的 `.sparkprofile` 文件不经过这个代理，而是按 AstrBot 获取附件的方式从聊天平台下载（遵循系统的代理环境变量）。

## 数据存储

数据位于 `data/plugin_data/astrbot_plugin_spark/`：

- `profiles.sqlite3`：通过链接下载的原始报告缓存，与分析是否成功无关，过期记录在访问缓存时清理。`.sparkprofile` 文件不进入缓存。
- `history.sqlite3`：开启历史功能后保存的报告概览和分析结果。关闭历史功能后不再写入，已有记录仍按 30 天保留期在插件加载时清理。
- `spark-*` 临时目录：分析期间存放解码后的报告（包括收到的 `.sparkprofile` 文件），分析结束即删除；AstrBot 异常退出导致残留时，插件下次加载时自动清理。

两个数据库独立存储。关闭历史功能或清除个人历史，不会删除报告缓存。报告信息会发送给你选择的模型，数据库请妥善保管。

缓存默认最多保留 64 份、原始数据合计 512 MiB，达到限额时优先淘汰最久未使用的报告，因此容量不足时可能早于设置的时间过期。SQLite 自动回收空闲页；数据库文件仍有索引与页开销，写入期间也可能产生临时文件。超大的运行元数据会截断并标注，避免向模型发送无界上下文。
